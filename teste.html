Motivation

The motivating question

How do we transform inconsistent, distributed tabular data into a trustworthy dataset that is ready for analysis and visualization?

Raw data → inspect → select → clean → transform → combine → reshape → validate → visualize → interpret

Enfatize que uma visualização pode estar tecnicamente correta e ainda ser analiticamente enganosa. Apresente a sequência como o mapa mental da aula. Tempo: 2 min.

Learning objectives

By the end of the lesson, you will be able to:

  • explain Series, DataFrame, labels, and data types;
  • inspect, select, filter, and modify tabular data;
  • diagnose missing, duplicate, invalid, and inconsistent values;
  • combine tables while validating key cardinality;
  • reshape data between wide and long forms;
  • build and validate a reproducible preparation pipeline;
  • explain how preparation choices affect a visualization.

Relacione cada objetivo a uma ação observável. Diga que os alunos deverão justificar decisões, não apenas reproduzir sintaxe. Tempo: 2 min.

Data Cleaning

Quality problems are not synonyms

Problem Meaning Typical response
Missing value not observed investigate, retain, fill, or remove
Invalid violates a domain rule verify, correct, quarantine
Duplicate repeated analytical unit define key, then deduplicate
Inconsistent same concept, different representation standardize
Outlier unusually distant but possibly valid investigate, do not auto-delete

Insista que outlier não é sinônimo de erro. O tratamento depende do modelo de geração dos dados e do objetivo. Tempo: 3 min.

Join types as set logic

Join Rows retained Teaching question
inner matched on both sides What overlaps?
left all left rows What happened to every observation?
right all right rows What metadata lacks observations?
outer union of keys Where are all mismatches? 
LEFT:  A B C      RIGHT:  B C D
inner → B C       left → A B C
right → B C D     outer → A B C D

Use o diagrama como lógica de conjuntos, lembrando que duplicidade de chaves altera a quantidade de linhas. Tempo: 2 min.

A reusable preparation function

def prepare_market_data(data, reference):
    out = data.copy()
    out["date"] = pd.to_datetime(out["date"], errors="coerce", format="mixed", dayfirst=True)
    out["instrument"] = out["instrument"].str.strip().str.upper()
    out["price"] = pd.to_numeric(
        out["price"].astype("string").str.replace(",", "", regex=False),
        errors="coerce"
    )
    out = out.drop_duplicates().loc[lambda d: d["date"].notna() & d["price"].gt(0)]
    out = out.merge(reference, on="instrument", how="left",
                    validate="many_to_one", indicator=True)
    assert len(out) <= len(data)
    return out

Explique entrada, saída, regras e contratos. Observe que esta função escolhe remover preço ausente, diferente do pipeline demonstrativo com imputação, para evidenciar que a política deve ser explícita. Tempo: 2 min.

Main conclusions

  1. pandas objects are labeled, and labels influence every operation.
  2. Cleaning begins with diagnosis, not deletion.
  3. Missing, invalid, duplicate, inconsistent, and unusual values require different reasoning.
  4. A merge encodes a relationship and should validate cardinality.
  5. Reshaping changes structure; aggregation changes information.
  6. Reliable visualization requires explicit units, types, keys, and assumptions.
  7. Assertions turn analytical expectations into executable checks.
