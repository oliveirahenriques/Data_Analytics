Apresente a aula como uma investigação de qualidade e estrutura. Explique que todos os dados são sintéticos e foram criados para fins didáticos. Tempo: 2 min.

Motivation

The central question

How can we turn incomplete, inconsistent, duplicated, and distributed tables into data that support a valid visualization?

Diagnose → clean → transform → combine → reshape → validate → visualize → interpret

Enfatize que limpeza e wrangling são decisões sobre significado, não apenas sintaxe. Tempo: 2 min.

Learning objectives

By the end of the lesson, students will be able to:

  • diagnose missing, duplicate, invalid, and inconsistent values;
  • make explicit and defensible cleaning decisions;
  • transform strings, categories, and numerical variables;
  • combine tables with concat, merge, and join;
  • validate key cardinality and audit unmatched records;
  • use MultiIndex, stack, and unstack;
  • reshape data with melt, pivot, and pivot_table;
  • explain how wrangling choices affect a visualization.

Relacione cada objetivo a uma ação observável. Tempo: 2 min.

Checkpoint 2: choose a treatment

For each case, choose retain, flag, correct, fill, or remove:

Keys and cardinality

Relationship Meaning
one-to-one each key appears once on both sides
many-to-one many observations reference one metadata row
one-to-many one left key matches multiple right rows
many-to-many duplicates on both sides may multiply rows

Use observações diárias para metadata como exemplo de muitos-para-um. Tempo: 2 min.

Join types as set logic

Join Keeps Main question
inner matched keys only What overlaps?
left every left row What happened to each observation?
right every right row Which metadata lacks observations?
outer union of keys Where are all mismatches? 
LEFT: A B C      RIGHT: B C D
inner → B C      left → A B C
right → B C D    outer → A B C D

Main conclusions

  1. Cleaning begins with diagnosis, not deletion.
  2. Missing, invalid, duplicate, inconsistent, and unusual values require different reasoning.
  3. Transformation choices should preserve an audit trail.
  4. A merge is a claim about keys and relationships.
  5. Reshaping changes structure; aggregation changes information.
  6. A tidy table may still support an invalid comparison.
  7. Trustworthy visualization depends on explicit rules, units, and validation.
